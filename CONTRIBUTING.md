## 🇪🇸 Castellano (Spanish)

¡Gracias por interesarte en mejorar este proyecto! Para mantener la calidad del código y la organización, por favor sigue estas pautas.

### 🛡️ Proceso de Revisión
Este repositorio tiene protegida la rama principal. Esto significa que:
* **No se permiten pushes directos** a `main`.
* Todas las mejoras deben pasar por un **Pull Request**.
* Cualquier cambio requiere la **aprobación del mantenedor** antes de ser integrado.

### 🛠️ Cómo contribuir

#### 1. Reportar Errores (Issues)
Si encuentras un bug, abre un "Issue" detallando:
* Pasos para reproducir el error.
* Comportamiento esperado vs. comportamiento actual.
* Tu entorno (sistema operativo, versión de lenguaje/herramienta).

#### 2. Enviar Cambios (Pull Requests)
Si quieres añadir una funcionalidad o corregir algo tú mismo:
1. Haz un **Fork** del repositorio.
2. Crea una rama para tu cambio (ej: `git checkout -b feature/nueva-mejora` o `fix/error-logueo`).
3. Realiza tus cambios y haz commits claros.
4. Haz un **Push** a tu fork y abre un **Pull Request** hacia la rama `main` de este repositorio.

#### 3. Estilo de Código
* Mantén el código limpio y comentado donde sea necesario.
* Sigue las convenciones de nombres ya existentes en el proyecto.

### 💬 Comunicación
Si tienes dudas sobre si una funcionalidad encaja en el proyecto, te recomiendo abrir un **Issue** de tipo "Propuesta" antes de empezar a programar para discutirlo.

## 🇺🇸 English

Thank you for your interest in improving this project! To maintain code quality and organization, please follow these guidelines.

### 🛡️ Review Process
The main branch of this repository is protected. This means:
* **Direct pushes to `main` are not allowed.**
* All improvements must be submitted via a **Pull Request**.
* Any changes require **maintainer approval** before being merged.

### 🛠️ How to Contribute

#### 1. Reporting Bugs (Issues)
If you find a bug, please open an "Issue" detailing:
* Steps to reproduce the error.
* Expected behavior vs. actual behavior.
* Your environment (OS, language/tool version).

#### 2. Submitting Changes (Pull Requests)
If you want to add a feature or fix a bug yourself:
1. **Fork** the repository.
2. Create a branch for your change (e.g., `git checkout -b feature/new-improvement` or `fix/login-error`).
3. Make your changes and write clear commit messages.
4. **Push** to your fork and open a **Pull Request** to the `main` branch of this repository.

#### 3. Coding Style
* Keep the code clean and commented where necessary.
* Follow the naming conventions already existing in the project.

### 💬 Communication
If you have doubts about whether a feature fits the project, I recommend opening a "Proposal" **Issue** before you start coding to discuss it.
